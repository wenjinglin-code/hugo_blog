硬件原理（priv-isa 13）

特权模式

HS-mode 和 S-mode 是一个东西，只是支持 hypervisor 改了名字，HS-mode 进入 VS-mode 通过 hstatus.spv = 1

CSR 访问

csr_hxxx 是 hs-mode 用来控制 vx-mode 的；csr_vsxx 是 vx-mode 访问 csr_sxxx 时，实际访问的寄存器

地址翻译

vstap 在 vx-mode 模式等价于 stap；hgatp 的 entry 是比 stap 的 entry 多两位的

riscv 是 32bit va → 34 bit pa， 所以 guest 转换出来的 pa 是 34 bit 的，所以 hgatp 要用 Sv32x4 在页表目录多 2 bit 索引，匹配所有的 gpa， 但是其他的 va 模式就没有必要，因为都能转换出 56 bit pa，其他这么做只是为了兼容？

应该不是为了兼容，是为了更好处理一种特殊情况，在不使用 mmu 都情况下，gpa 是可以大于 56 bits 的，Sv39/Sv48/Sv57 将不能覆盖（只能转换为 56 bits pa），使用 Sv39x4/Sv48x4/Sv57x4 将可以扩大 4 倍

中断类型

G-stage 翻译失败会触发 guest-page fault

 50    assert(userspace_addr > 0);
 51    /* read tiny_kernel binary into the memory */
 52    ret = read(tiny_kernel_fd, userspace_addr, PAGE_SIZE);
 53    assert(ret >= 0);
 54
 55    /* set user memory region */
 56    mem.slot = 0;
 57    mem.flags = 0;
 58    mem.guest_phys_addr = 0;
 59    mem.memory_size = PAGE_SIZE;
 60    mem.userspace_addr = (unsigned long)userspace_addr;
 61    ret = ioctl(vm_fd, KVM_SET_USER_MEMORY_REGION, &mem);
 62    assert(ret >= 0);
 63
 64    /* get kvm_run */
 65    mmap_size = ioctl(kvm_fd, KVM_GET_VCPU_MMAP_SIZE, NULL);
 66    assert(mmap_size >= 0);
 67    kvm_run = (struct kvm_run *)mmap(NULL, mmap_size, PROT_READ | PROT_WRITE, MAP_SHARED, vcpu_fd, 0);
 68    assert(kvm_run >= 0);
 69
 70    /* set cpu registers */
 71    ret = ioctl(vcpu_fd, KVM_GET_SREGS, &sregs);
 72    assert(ret >= 0);
 73    sregs.cs.base = 0;
 74    sregs.cs.selector = 0;
 75    ret = ioctl(vcpu_fd, KVM_SET_SREGS, &sregs);
 76    memset(&regs, 0, sizeof(struct kvm_regs));
 77    regs.rip = 0;
 78    ret = ioctl(vcpu_fd, KVM_SET_REGS, &regs);
 79    assert(ret >= 0);
 80
 81    /* vcpu run */
 82    while (1) {
 83        ret = ioctl(vcpu_fd, KVM_RUN, NULL);
 84        assert(ret >= 0);
 85
 86        switch(kvm_run->exit_reason) {
 87            case KVM_EXIT_HLT:
 88                printf("----KVM EXIT HLT----\n");
 89                close(kvm_fd);
 90                close(tiny_kernel_fd);
 91                return 0;
 92            case KVM_EXIT_IO:
 93                putchar(*(((char *)kvm_run) + kvm_run->io.data_offset));
 94                break;
 95            default:
 96                printf("Unknow exit reason: %d\n", kvm_run->exit_reason);
 97                break;
 98        }
 99    }
100
101    return 0;

vcpu 中断虚拟化（aplic 软件模拟，硬件使用 imsic g-file）（代码分支 riscv_kvm_aia_hwaccel_v1 ）

参考文档：AIA_Virtualization_in_KVM_RISCV_final.pdf

硬件原理（isa, riscv-interrupt）

isa

  • 写 g-file 的时候，in host，会触发 Supervisor guest external interrupt (SGEIP); in guest，就触发 Virtual supervisor external interrupt (VSEIP)，陷入 host

  • 配置 hideleg，可以将 Virtual supervisor external interrupt 直接由 vs 模式处理；在vs 中，Virtual supervisor external interrupt 会转换为 supervisor external interrupt，以便相同代码可以直接在 vs 执行；

  • hip.VSEIP = hvip.VSEIP | hgeip.(hstatus.VGEIN) | vs interrupt signal，hip.VSEIP 只能通过 hvip.VSEIP 清；

    hs 模式下，写 g-file 是触发 sge；

    vs 模式下， hideleg[10] ≠ 1 时，触发 vse 的时候，vs 会陷入 hs，hs 通过 hip 识别 vse 中断，hvip 清中断；

    hideleg[10] = 1 时, vsip.SEIP/E ←→ hip.VSEIP/E, 因此 guest 可以直接控制 sip.SEIP 控制 vsip.SEIP 进而控制 hip.VSEIP

  • hip.SGEIP = hgeip[hstatus.VGEIN] & hgeie[hstatus.VGEIN] （hgeip 长度 = HSXLEN）

IMSIC

hstatus.VGEIN （0 s-file，1 - max guest index g-file）决定了当前的 hart 选择了哪个 g-file 作为 imsic 的 interrupt file，vs 依旧可以使用原来的 siselect, sireg, and stopei 控制 imsic interrupt file

aplic 需要软件模拟（arch/riscv/kvm/aia_aplic.c），imsic 通过 g-file 实现虚拟化
